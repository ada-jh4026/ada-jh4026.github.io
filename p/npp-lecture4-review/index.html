NPP Lecture 4 Review: Python Data Structures & Classes (OOP and Deep Learning)

Topics: built-in data structures · mutability · standard-library containers · classes & inheritance · magic methods · PyTorch nn.Module

Part 1: Core data structures

1. Objects and name binding

  • Every Python datum is an "object".
  • Python uses duck typing: functions accept any object (unlike C/Java).
  • = binds an object to a name.
x = 7
y = x          # y and x point to the same object
a = list([1,2,3,4])
b = a          # b and a point to the same list (shallow binding!)

2. Mutable vs immutable

Type Mutability
int / float / str / complex / tuple / frozenset immutable
list / set / dict mutable
  • "Updating" an immutable object actually creates a new object — verify with id().
x = 3
print(id(x)); x += 5; print(id(x))   # id changes → new object
  • Small-integer cache: Python caches the integers −5 to 256.
x = 3; y = 3
print(x is y)          # True (same cached object)
a = 12345; b = 12345
print(a is b)          # False
  • Python integers are arbitrary precision, bounded only by memory (sys.getsizeof()).

3. Lists

  • Create with [] or list(): [1,3,5], list((3,4,5)), [_ for _ in range(6,10)].
  • Properties: mutable, one-dimensional (single index), ordered; a collection of other objects; supports iteration.
  • Fast: look up / change elements, append/remove the last element.
  • Slow: add/remove elements other than the last (cost scales with length — the whole block shifts).
  • Implementation: CPython lists are a block of memory addresses; spare space is preallocated, and a full list must be copied wholesale.

List comprehensions

  • [_ for _ in range(6, 10)] is usually the fastest way to build a list (20–25% faster than a for+append loop); prefer it while it stays readable.

4. Tuples

  • Create with commas (usually ()) or tuple(): 1,3,5, (2,3,4), tuple([3,4,5]).
  • Properties: immutable, one-dimensional, ordered — the immutable equivalent of a list.
  • Fast at lookup; slightly less memory than a list (block sized exactly, no spare room).
  • Use a tuple when something should never change.
  • Unpacking: a, b, c = 1, 2, 3 — often used to collect multiple return values.

5. Generators

  • There is no "tuple comprehension"; (x**2 for x in range(3)) is a generator.
  • A generator can be iterated only once; it doesn't store its contents but yields values on demand and discards them — memory-efficient.
  • Easy to trip over:
gen = (x for x in range(4))
print(list(gen))   # [0, 1, 2, 3]
print(list(gen))   # [] (already exhausted!)

6. Sets and frozensets

  • Create with {} or set(): {1,3,5}, set([3,4,5]).
  • Properties: unordered, mutable, a collection of distinct objects.
  • x in S is very fast (orders of magnitude faster than a list).
  • Implementation: a hash table — a large (mostly empty) block plus a hash function mapping values to slots 0..N−1.
    • Add: hash the value → insert at that slot.
    • Lookup: hash the value → check that slot.
    • Collisions (two values hashing to the same slot) are resolved by probing a predictable pattern until the target or an empty slot is found → sets must stay sparse, using more memory than lists.
  • frozenset: the immutable version of a set.

7. Dictionaries (dict)

  • Map keys → values: {"a":1,"b":10}, dict(x=1,y=2), {x:x**2 for x in range(10)}.
  • Like sets, optimized for x in D (fast key lookup).
  • Keys must be immutable and hashable (no lists as keys).
  • Implementation: a hash table like a set, but:
    • a dict stores both the key and (the address of) the value object;
    • a dict preserves insertion order (Python 3.7+), a set does not.
  • Dict comprehensions build dicts quickly, but aren't always faster than a loop (e.g. reversing a dict is about equal).

8. Choosing a data structure

  • Ordered + mutable + indexable → list; fixed → tuple.
  • Deduplication / fast in tests → set; fixed → frozenset.
  • key→value mapping / fast key lookup → dict.
  • Memory-efficient, iterate once → generator.

Part 2: Standard-library extension types

9. The array module

  • Stores a homogeneous collection (one type), more memory-efficient than a list (values, not pointers).
  • But awkward to use; most people ignore it — prefer NumPy.
import array
a = [1,2,3,4,5]
b = array.array('b', a)   # more compact

10. The collections module

Type Notes
namedtuple tuple-like with named fields
deque list-like, fast append/pop at both ends
OrderedDict insertion-ordered dict (now redundant since dicts are ordered; still in legacy code)
defaultdict auto-provides a default value for missing keys via a factory, e.g. defaultdict(int)

Part 3: NumPy / Pandas recap

  • numpy.ndarray: multidimensional arrays (1-D to 64-D); all elements must share one type; if no dtype is given, NumPy picks one that fits the input.
np.array([0,1,2])       # int64
np.array([0,1,2.5])     # float64
np.array([0,'hat',sum]) # object
  • pandas.Series: a labelled 1-D array; pandas.DataFrame: a table with an index and named columns.
  • See Lecture 2 for details.

Part 4: Python classes

11. OOP and encapsulation

  • A class = a custom data structure bundling data (attributes) with the functions (methods) that act on it.
  • Benefit: encapsulation — binding data and methods together makes it harder to apply them to the wrong object.
class MyClass:
    """This is my cool class."""
    def my_method(self, a, b):
        self.val = a + b     # store an instance attribute
        return a * b

inst = MyClass()             # create an instance with ()
a = inst.my_method(1, 2)     # a=2, inst.val=3

12. __init__ and instance attributes

class Point3D:
    def __init__(self, x, y, z):
        self.x = x; self.y = y; self.z = z

p = Point3D(1, 4, 7)
print(p.x, p.y, p.z)   # 1 4 7

13. Class attributes vs instance attributes (⚠️ common pitfall)

  • Class attributes (written in the class body, outside methods): shared by all instances.
  • Instance attributes (self.xxx): independent per instance.
class MyClass:
    mylist = []            # class attribute — shared by all instances!

inst1, inst2 = MyClass(), MyClass()
inst1.mylist.append(1); inst2.mylist.append(2)
print(inst1.mylist is inst2.mylist)   # True (the same list!)

Mutable types (like a list) as class attributes are especially dangerous — instances interfere with each other.

14. Inheritance

class MySubClass(MyBaseClass):
    '''MySubClass inherits from MyBaseClass'''
    # new methods here
  • Every class ultimately inherits from the base object (including int, list, …).
  • A subclass can override parent methods.
  • Inspect the base: Tree.__base__.
  • super() calls the parent's method without rewriting it entirely.
class Shrub(Tree):
    def __init__(self, species, age, height, fruit):
        super().__init__(species, age, height)   # call the parent __init__
        self.fruit = fruit

15. Properties: make a function feel like an attribute

class Temperature:
    def __init__(self, temp):
        self.celsius = temp

    @property
    def fahrenheit(self):
        return self.celsius * 9/5 + 32

    @fahrenheit.setter
    def fahrenheit(self, temp):
        self.celsius = (temp - 32) * 5/9

16. Magic (special) methods

Trigger Method
inst() __call__(self)
print(inst) __str__(self)
inst (interactive display) __repr__(self)
inst1 + inst2 __add__ (operator overloading)
  • Overloading rule: don't surprise people — + should add/append, - should subtract/remove.

17. __new__ and __del__ (advanced — skippable)

  • Creating an instance calls __new__ then __init__ (usually you only write __init__).
  • __del__ runs when the garbage collector considers the object no longer needed — use it for special cleanup.

Part 5: Classes and deep learning (PyTorch)

18. From a neuron to PyTorch

Base neuron (linear model: weighted sum + bias):

class Neuron:
    def __init__(self, weights, bias):
        self.weights = weights; self.bias = bias
    def forward(self, inputs):
        return sum(w*i for w,i in zip(self.weights, inputs)) + self.bias

Add activation functions via inheritance (ReLU / Sigmoid):

class ReLUNeuron(Neuron):
    def relu(self, x): return max(0, x)
    def forward(self, inputs):
        return self.relu(super().forward(inputs))   # parent computes linear, then activate

19. PyTorch's nn.Module

  • In PyTorch, everything "neural" inherits from torch.nn.Module, which manages parameters, device movement, save/load, and autograd.
  • Key points:
    • super().__init__() initialises the parent.
    • nn.Linear registers learnable parameters automatically.
    • forward defines the computation.
class CustomNeuron(nn.Module):
    def __init__(self, input_size):
        super().__init__()
        self.linear = nn.Linear(input_size, 1)
        self.relu = nn.ReLU()
    def forward(self, x):
        return self.relu(self.linear(x))

Multi-layer perceptron (MLP):

class TinyMLP(nn.Module):
    def __init__(self, input_size, hidden_size, num_classes):
        super().__init__()
        self.fc1 = nn.Linear(input_size, hidden_size)
        self.act = nn.ReLU()
        self.fc2 = nn.Linear(hidden_size, num_classes)
    def forward(self, x):
        return self.fc2(self.act(self.fc1(x)))

20. Key takeaways

  • Classes encapsulate data (attributes) and behaviour (methods).
  • Inheritance lets you define a blueprint once and specialise it in subclasses.
  • PyTorch uses this pattern everywhere: models and layers inherit from nn.Module, providing parameter handling, device management, and autograd integration.
  • Understanding classes and inheritance makes DL frameworks more transparent and your own models easier to design, debug, and extend.

Common pitfalls ⚠️

  1. Mutable types (list/dict/set) as class attributes are shared across instances — put them in __init__ instead.
  2. Generators can be iterated only once.
  3. a = b for a mutable object is a shallow binding (same object) — mutating a affects b.
  4. Dict keys must be immutable and hashable.
  5. Use super() to extend (rather than fully replace) parent logic in a subclass.
