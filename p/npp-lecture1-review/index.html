Part 1: Intro to Computer Science (morning)

1. Why Python?

  • An interpreted, general-purpose programming language; popular and in high demand.
  • Competes with R in the data-science space and has a huge ML/deep-learning ecosystem.
  • "Easy to do simple things, not too hard to do complex things, possible to do really complex things."

2. Hello World and the command line

print("Hello World!")
  • Save it as a .py file and run it in a terminal with python scripts/hello_world.py.
  • In Jupyter/IPython, ! runs a shell command and % runs a magic command; neither may be used in a plain Python (.py) file.

re quick reference

import re
re.findall(pattern, text)   # all matches
re.search(pattern, text)    # search anywhere (first match)

  • . matches any non-newline character; * matches 0+ of the previous; \w matches word characters.

math and numpy don't always mix

import math, numpy as np
math.sin(np.pi/6)      # OK — Python understands numpy scalars
arr = np.array([0, np.pi/6, np.pi/2])
np.sin(arr)            # OK — vectorized
math.sin(arr)          # ERROR — Python doesn't understand numpy arrays

5. Time/space complexity (Big O)

Think of a computer as a Turing machine: every algorithm is a trade-off between space (memory) and time (runtime).

  • my_max(x): one pass to find the max → grows linearly, $\mathcal{O}(n)$.
  • find_duplicates(x): nested loops → grows quadratically, $\mathcal{O}(n^2)$.
  • permute(x): generate all permutations → time and output space grow factorial, $\mathcal{O}(n!)$.

Use %timeit (Jupyter magic) to measure runtime and a log-log plot to read off the order.

6. Computer architecture and the storage hierarchy

  • Low level: doped silicon wafers form transistors in logic circuits.
  • Storage layers (faster/more expensive at the top): CPU registers → CPU cache → RAM → disk.
  • Moving data between layers costs time → computers are faster on "nearby" data.
  • All modern computers are binary: high voltage = "on", low voltage = "off".

7. Binary and integer representation

Positive integers

$2381$ expands by place value; binary $1001_2 = 1\cdot8+0\cdot4+0\cdot2+1\cdot1 = 9_{10}$.

int("1001", base=2)   # 9
bin(9)                # '0b1001'
bin(int(3.5))         # 3  -> can't do bin(3.5)

Two storage schemes:

  1. Store "how many bits + the number itself" → Python uses this, giving arbitrary-precision integers (bounded by memory).
  2. Fixed bit count with leading zeros → NumPy uses this (efficient, interoperable with C).

Integer overflow

Fixed-width integers overflow. An 8-bit unsigned 11111111 (255) + 1 wraps to 0:

import numpy as np
x = np.array([int("11111111", 2)], dtype=np.uint8)   # 255
(x + 1)[0]   # -> 0 (overflow wraparound)

Negative integers: two's complement

  • Option 1 (sign bit): steal the top bit for the sign — needs separate add/subtract circuitry, complicated.
  • Option 2 (two's complement): the top bit carries weight $-2^{n-1}$. In 4 bits, $-3 = 1101_2$ ($-8+4+1=-3$).
    • Addition works the same as unsigned: $-3+3 = 1101+0011 = 0000 = 0$.
    • Negate by flipping all bits and adding 1: $-3=1101 \to 0010+1=0011=3$.
np.binary_repr(3, width=4)    # '0011'
np.binary_repr(-3, width=4)   # '1101'

8. Characters and text encoding

  • Computers store only binary, so characters must be encoded as numbers.
  • The most famous encoding is ASCII (American Standard Code for Information Interchange).
  • Python 3 defaults to Unicode (utf-8), covering nearly every world language.
  • Text is stored as a sequence of code points, plus its length/end position.

Part 2: Floating-point arithmetic (afternoon)

The core mystery: why is $0.1 + 0.2 \ne 0.3$?

9. The IEEE-754 standard

Established in 1985 by the IEEE to fix inconsistencies between manufacturers (previously $a+b$ differed across machines).

Any non-zero real $x$ can be written in normalised binary scientific notation:

$$x = (-1)^{s} \times (1.f)_{2} \times 2^{e-\text{bias}}$$

  • sign $s$: 1 bit.
  • exponent $e$: 8 bits (single) or 11 bits (double) — stored with a bias added.
  • mantissa (significand) $f$: 23 bits (single) or 52 bits (double); the leading 1 is implicit (not stored), so precision is one bit more.
Precision Total bits Sign Exponent Mantissa
single (float32) 32 1 8 23
double (float64) 64 1 11 52
quadruple 128 1 15 112

Don't memorise — query np.finfo().

Single precision (32-bit)

$$x = (-1)^s \times (1.f)_2 \times 2^{e-127}$$

  • Exponent $e$: $0 < e < 255$; $e=0$ is reserved for $\pm0$ and subnormals, $e=255$ for $\pm\infty$ and NaN. Bias = 127, so the true exponent ranges $2^{-126}$ to $2^{127}$.
  • Mantissa $m=1.f$: $1 \le m \le 2 - 2^{-23}$.
  • Largest number $\approx (2-2^{-23})\cdot 2^{127} \approx 2^{128} \approx 3.4\times10^{38}$.
  • Smallest positive normal $= 2^{-126} \approx 1.18\times10^{-38}$; subnormals reach $2^{-149}\approx1.4\times10^{-45}$ (at the cost of precision).

Double precision (64-bit)

$$x = (-1)^s \times (1.f)_2 \times 2^{e-1023}$$

  • 11-bit exponent, bias = 1023; 52-bit mantissa.
  • Largest $\approx 2^{1024} \approx 1.8\times10^{308}$; smallest positive normal $\approx 2^{-1022}\approx2.2\times10^{-308}$; subnormals to $2^{-1074}\approx4.9\times10^{-324}$.

Machine epsilon ε

  • Machine numbers: the finite set of exactly representable reals; the machine number for $x$ is $\mathrm{fl}(x)$.
  • Machine ε: the distance between $1$ and the next larger machine number.
    • Single: $\epsilon = 2^{-23} \approx 1.19\times10^{-7}$.
    • Double: $\epsilon = 2^{-52} \approx 2.22\times10^{-16}$.
  • Because we round to the nearest machine number, $\mathrm{fl}(1+x)\ne1$ as soon as $x > \epsilon/2$.

Precision and resolution

  • Single: 23 mantissa bits → $\log_{10}(2^{23})\approx6.9$, i.e. 6 reliable significant digits, resolution $10^{-6}$.
  • Double: 52 mantissa bits → $\log_{10}(2^{52})\approx15.65$, i.e. 15 reliable significant digits, resolution $10^{-15}$.
import numpy as np
f = np.finfo(np.float64)
print(f.bits, f.nmant, f.nexp)   # total / mantissa / exponent bits
print(f.max, f.tiny, f.eps)      # largest / smallest normal / machine epsilon
print(f.precision, f.resolution)

10. Rounding, overflow and underflow

  • Every operation rounds: $\mathrm{fl}(\mathrm{fl}(a)+\mathrm{fl}(b))$.
  • Underflow: numbers below the smallest normal first lose precision (subnormals) and eventually round to zero.
  • Overflow: IEEE-754 default is $\pm\infty$ (e.g. 1e308 * 10 → inf); some operations raise OverflowError (e.g. 2.0**10000, math.exp(1000)).

11. The five "surprises" — must understand

Surprise 1: $1 + x \ne 1$ does not hold

x = 1e-16
print(1 + x != 1)   # False

Reason: $x=10^{-16} < \epsilon/2\approx1.11\times10^{-16}$, so $1+x$ rounds back to machine number $1$. With $x=2\times10^{-16}$ ($>\epsilon/2$ but $<\epsilon$), 1 + x != 1 is True.

Surprise 2: $0.1+0.2\ne0.3$

print(0.1 + 0.2 == 0.3)   # False

Reason: a finite decimal may not be finite in binary. $(0.1)_{10}=(0.0001100110011\ldots)_2$, like $0.3333\ldots$ in decimal. fl(0.1)+fl(0.2) rounds to something other than fl(0.3).

Surprise 3: associativity fails

a, b, c = 1e16, -1e16, 1.0
print((a+b)+c == a+(b+c))   # False

Reason: every operation rounds. $(a+b)+c = 0+1 = 1$, but $a+(b+c)=1e16+(-1e16)$; $b+c$ rounds back to $-1e16$, giving 0. Machine numbers are not evenly spaced (sparser for larger magnitudes).

Surprise 4: catastrophic cancellation

a, b = 1.0000001, 1.0000000
print(a - b == 1e-7)   # False

Reason: subtracting two nearly-equal numbers. $\mathrm{fl}(1.0000001)$ carries a tiny rounding error; the subtraction itself is exact (Sterbenz lemma), but the leading 1.000000 cancels, so the absolute error stays while the result shrinks $10^7\times$ — the relative error is amplified about $10^7\times$. In general:

$$\text{relative error}\lesssim\frac{|a|+|b|}{|a-b|}\cdot\frac{\epsilon}{2}$$

  • Subtraction doesn't create error — it exposes the rounding errors already in $a,b$; the closer they are, the worse the amplification.
  • Remedy: rewrite formulas to avoid subtracting nearly-equal numbers, e.g. $\sqrt{x+1}-\sqrt{x}=\dfrac{1}{\sqrt{x+1}+\sqrt{x}}$.

Surprise 5: accumulated error

a, b = 100, 0.1
s = 0
for _ in range(a):
    s += b
print(a * b == s)   # False

Reason: the error in fl(0.1) accumulates over 100 iterations.

12. Take-home message

Never compare floats with ==! Use

$$|a-b|<\text{tol}$$

or simply:

np.isclose(0.1+0.2, 0.3, atol=1e-15, rtol=1e-5)

13. Companion exercises

  1. dec2bin: integer part — repeated division by 2 (remainders reversed); fractional part — repeated multiplication by 2 (take the integer part), capped at max_fractional_digits (52) to avoid infinite loops.
  2. Counting machine numbers: use itertools.product to enumerate all bit combinations, then deduplicate and count.
  3. IEEE-754 encode/decode: convert a decimal to its 32/64-bit string, or a bit string back to decimal (sign + exponent + mantissa concatenation).
